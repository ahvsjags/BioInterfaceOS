# T124: External protected-data evaluation readiness

## Purpose

Create the auditable handoff boundary for an evaluator who is independent of
the author team and holds protected real observations. This task is not a
substitute for that evaluator, and it must not turn a fixture lockbox receipt
into evidence for an empirical claim.

## Preconditions

T120--T122 are complete. T123 remains blocked because no compatible
cross-study target has been admitted. The historical `lockbox evaluate`
workflow is fixture-contract-only and cannot satisfy this task.

## Non-goals

Do not inspect, copy, download, synthesise or infer protected values. Do not
name an evaluator, create a signature on their behalf, train a model, change a
threshold, or report a metric as if independent evaluation had occurred.

## Interfaces and invariants

- Protocol: `docs/data/R2_INDEPENDENT_EVALUATION_PROTOCOL.json`.
- External aggregate-only receipt schema:
  `schemas/independent_evaluation_receipt.schema.json`.
- Readiness command: `python -m biointerfaceos lockbox evaluate-independent --strict`.
- Readiness outputs: `reports/review_round_2/independent_evaluation/v1.0.0/`.
- T123 must expose an admitted compatible target and frozen real-model output
  before an evaluator can be released a frozen bundle.
- The protected data stay outside this repository. A public receipt may contain
  aggregate metrics and hashes only; it may never contain protected rows or
  author-team access to them.
- An external evaluator must attest to identity/affiliation, conflict status,
  frozen bundle hashes, environment, no author access, no post-freeze tuning,
  and no raw-value export.

## Implementation plan

1. Freeze the protocol's independence, protected-data, frozen-bundle and
   receipt requirements.
2. Read the immutable T123 compatibility decision and receipt, checking their
   hash binding and the compatible-target count.
3. Emit a one-shot readiness receipt that is explicitly blocked until the T123
   target, model, paired ablations, OOD report and negative controls exist.
4. Add strict-mode and tamper-rejection regression tests.
5. When T123 becomes ready, issue a new protocol version, freeze the bundle,
   and give it to an evaluator outside the author environment. Their signed
   aggregate-only receipt remains a required external input; it is not
   generated by this repository.

## Discoveries

The T123 receipt reports zero compatible targets and no model, ablation, OOD,
or negative-control run. The correct readiness result is therefore blocked,
not an evaluator-backed outcome.

## Decisions

The protocol is stored as a development-only artifact and has exploratory
claim level. Only a later external receipt with the frozen bundle and
protected observations can support evaluator-backed statements.

## Validation

- `python -m pytest tests/lockbox/test_independent_evaluation_workflow.py -q`
- `python -m biointerfaceos lockbox evaluate-independent --strict`
- `python scripts/validate_execution_pack.py`

The current command must return a valid blocked readiness audit with zero
compatible targets and every evaluation/result field set to `false`.

## Failure recovery

If any T123 input differs from its receipt hash, or the protocol weakens data
separation, stop. If the compatible target is unavailable, retain the blocked
receipt and continue source admission; never substitute a fixture or a
heterogeneous endpoint.

## Outputs

The protocol, workflow, CLI command, strict regression tests, immutable
readiness report and receipt, this plan, and task-ledger evidence.

## Completion note

The implementation path is complete when its gate and documentation are
validated. The T124 task remains blocked until an independent evaluator uses
protected real observations with a T123-frozen bundle.

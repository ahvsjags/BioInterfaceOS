# R4-T246 paper-data candidate screen: PMC11328176 multicore corona dataset

Status: `ADMITTED_TECHNICAL_SENSITIVITY_ONLY`

This screen records a real, byte-verified supplementary dataset obtained from
the article-level PMC AWS distribution. It is admitted to the BioInterfaceOS
development evidence ledger as a technical cross-core sensitivity source. It
is not admitted as an independent biological cohort, lockbox, or external
validation source.

provenance coordinates and are never counted as three biological units.

## What this closes

1. A second, independently published and openly redistributable multicore
   technical source is now available as real binary input.
2. Six additional core-facility processing anchors and 70 overlap targets can
   be used for a study-held-out technical portability sensitivity analysis.
3. The route is reproducible from an official PMCID package, SHA-256 manifests,
   and a row-level source map rather than a prose-only assertion.

## What this does not close

The study distributes standardized material to core facilities; it does not
provide six independent donor cohorts. The biological unit is therefore one
common prepared corona/plasma source with technical core-facility replication.
The source cannot be used to increase biological effective `n`, to claim
independent biological validation, to replace a protected lockbox evaluator,
or to satisfy no-author external scientific reproduction.

The T195 nine-target common set is not changed: `P60174` is absent from this
six-core source, so the candidate is a sensitivity source rather than a new
three-source target-freeze route.

## Frozen technical execution

The source was connected to the existing sequence ridge workflow after the
source map and the 99-member target universe were fixed. The execution uses
six leave-one-core-out outer folds, nested alpha selection on the five
development cores, full-sequence versus amino-acid-composition-only paired
ablation, 256 within-development-core target permutations per fold, and a
2,000-resample core-cluster bootstrap.

| Endpoint | Result |
|---|---:|
| Full sequence ridge mean held-out Spearman | `0.509683` |
| Full sequence ridge core bootstrap 95% interval | `[0.391177, 0.612970]` |
| Composition-only mean held-out Spearman | `0.432724` |
| Composition-only core bootstrap 95% interval | `[0.321803, 0.530572]` |
| Paired full-minus-composition mean Spearman | `0.076958` |
| Minimum held-out target count | `11` |
| Outer folds / technical batch clusters | `6 / 6` |

The execution receipt and all prediction, nested-selection, ablation,
permutation, and parameter artifacts are under
`reports/review_round_4/pmc11328176_multicore_technical_execution/v1.0.0/`.
The result supports technical cross-core portability sensitivity only; the
bootstrap cluster is a core-facility cluster, not a donor cluster.

## Decision for the strong-Q1 goal

`ADMIT_TECHNICAL_SENSITIVITY_ONLY`. This materially strengthens data
compatibility, source licensing, and technical portability evidence, but it

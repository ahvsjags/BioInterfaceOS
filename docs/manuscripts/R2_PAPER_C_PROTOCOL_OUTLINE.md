# A results-blind independent-evaluation protocol for candidate biointerface expressions

## Scope and status

This is a results-blind R2 Paper C protocol outline. It is **not
submission-ready** and contains no evaluated candidate status. Historical
fixture pre-lock outputs are not evidence for this protocol.

## Research question and protocol contribution

The protocol asks whether predeclared candidate expressions can be assessed by
an evaluator outside the author team using a frozen real-data bundle and
protected observations. Its contribution is the audit trail and decision rule,
not a claim that an expression has been confirmed, contradicted or discovered.

## Candidate and target-admission boundary

Candidates may be defined only after T123 admits a single cross-study target
with source-defined statistic, unit, biological condition and independent
unit. The current receipt has zero compatible targets, so the candidate set,
threshold ledger and prediction archive are unavailable by design.

## Current target-admission evidence

The current three-source author-result profile has zero compatible cross-study
targets. T129 then screened two CC0 candidate workbooks from two laboratories
and a separate two-source expansion from one laboratory. A current consolidated
receipt also records the source-mapped PXD030327 exposure design, giving eight
candidate sources from five disclosed laboratories and thirty-one verified source assets;
all eight candidates remain non-admitted. The source labels, author result
tables and file paths are not reinterpreted as numeric covariates, biological
replicates or a common endpoint. Consequently the target remains `NOT_FROZEN`,
model use remains `PROHIBITED`, and no candidate, threshold ledger, prediction
archive or evaluator handoff exists.

T140 separately records an article-level UCD/PNNL two-laboratory candidate pair
with a nominal shared 50/100 nm polystyrene design. The pair is not part of the
T129 cohort: first-party supplementary bytes, reuse terms, unit-level maps and
shared preprocessing/endpoint evidence remain outstanding, so it cannot create
a candidate, target, model result or evaluator handoff.

## Frozen analysis and evaluator handoff

Before protected evaluation, freeze the Git commit, environment lock, target
registry, split manifest, model configuration, predictions and thresholds. The
external evaluator receives that bundle once; any change creates a new protocol
version and prevents comparison with the original receipt.

## Protected-data and independence safeguards

The evaluator must not be an author, must disclose conflicts and uses a
separate environment. Protected observations remain outside the repository.
Only aggregate metrics, status decisions, hashes, environment digest and a
signed attestation may enter the receipt. The author team cannot access values
or tune after freezing.

## Related work and comparator boundary

Position the protocol against bio-nano reporting, declared OOD practice,
life-science ML reproducibility and registered-report principles. The protocol
does not turn preregistration into validation, and it does not use external
studies as unadmitted data or baselines.

## Predeclared aggregate reporting

The evaluator receipt must report every preregistered aggregate metric,
threshold status, overlap, effective sample size, calibration, uncertainty,
abstention and deviation. It must not export raw values, hide failures, rewrite
predictions or alter thresholds.

## Figures, data, code and availability

Use R2 Figures 1 and 3 only as protocol diagrams. Attach the evaluator receipt
schema, frozen-bundle hashes, access boundary and public software replay
materials. These artifacts document the protocol; they do not supply a result.

## Limitations and transition criteria

The only route to a results manuscript is a compatible T123 target followed by
a valid T124 aggregate-only signed external-evaluator receipt. A later external
scientific reproduction is required before any broader empirical designation.
